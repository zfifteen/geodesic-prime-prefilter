Japanese Line Geometry to Literal Multiplicative Web

Formal experiment planning document for importing structural invariants from visual line multiplication (diagonal filtering, cross-family crossings, propagation, witness completeness) into the public-thread triangulation method for semiprime neighborhood analysis.

1. Executive Summary

The Japanese (line/stick) multiplication method encodes multiplication as the geometry of two bundles of parallel lines whose crossings are spatially sorted into place-value diagonals. The result is read from coherent structure across bands plus deterministic propagation (carry), not from a single global maximum count.

The current literal multiplicative-web / thread-triangulation work (see literal_web_hole_trace.py and REWIND_TO_LITERAL_WEB.md) already uses a 1D thread-crossing model but scores primarily via flat support cardinality. This document defines four narrow, deterministic, PGS-native experiments that test whether Japanese-style geometric invariants measurably improve nomination of held-out factor distances under the strict public-web contract.

Primary hypothesis (highest leverage):
Replacing or augmenting flat thread support cardinality with multi-scale banded (“diagonal”) filtering and explicit cross-family crossing rules will increase the rank and visibility of true factor-distance holes in the public output, even when raw max support remains low (as observed in the toy ladder where max support was frequently 3).

3. Japanese Structural Invariants (Mapped)

Japanese Mechanism

  • Bundles = digit values (cardinality)
  • Crossings = exact m×n witnesses (no arithmetic multiply)
  • Diagonals = spatial filter by total degree i+j (place-value grouping)
  • Two distinct directions = two multiplicand families
  • Carry = deterministic local propagation between bands
  • Completeness = every term has exactly one witness in the correct band

Literal Web Counterpart (Current)

  • Threads = small-prime arithmetic progressions (period r, phase −N mod r)
  • Support at t = cardinality of threads through t
  • Flat global max-support (or simple top-k)
  • Undifferentiated pool of small primes
  • No propagation step
  • Support count only; no coverage or completeness signature

5. Primary Experiment Specification — Banded Diagonal Support

Experiment ID: LWM-BAND-01
Branch constraint: Literal web only. No return to ratio/candidate pruning machinery.
Public contract: public web evidence → banded support table → emitted nominated offsets → audit membership

5.1 Observable Object

The public factor-thread web around N (identical input to literal_web_hole_trace.py).

5.2 Mechanism (Ordinary Language)

Instead of counting every small-prime thread equally, group the threads into 2–4 deterministic scale bands. For each offset, compute both per-band support and a cross-band coherence score. The public output now includes the set of offsets that are locally maximal under the coherence rule, not merely global raw count.

5.3 Formal Definition (PGS-Native Frame)

Let T be the multiset of public small-prime factors observed in the held-out window. Define a deterministic partition function B: T → {B1, B2, …, Bk} (k=3 recommended for first run) based on either:

  • Bit-length of r (public, scale-invariant), or
  • Local PGS state at the composite where r was observed (GWR winner position relative to chamber, excess τ under DNI normalization).

Support vector at offset t: S(t) = (count in B1, count in B2, …, count in Bk).

Coherence score C(t) = a deterministic function of S(t) (e.g., minimum non-zero band count, or count of bands above a public threshold, or simple product of normalized per-band ranks).

Emitted holes = offsets with maximal C(t) (or top-m under C, with tie-break by |t| then raw total support).

5.5 Implementation Boundaries (Strict)

  • Band assignment rule must be fully public and deterministic (no p/q or audit labels used to choose bands).
  • All existing holdout logic unchanged.
  • Output artifacts must include both the old flat view and the new banded view for direct comparison.
  • No candidate generation, no pruning, no residue certificates in the nomination path.
  • GWR/DNI used only as optional thread-typing features (secondary band definition); raw prime r remains a valid first-run band key.

6. Secondary Experiments (Follow-on)

  1. LWM-CROSS-01 — Cross-family scoring (left vs. right origin threads scored separately, inter-family alignments promoted).
  2. LWM-PROP-01 — Deterministic local propagation rule between adjacent high-coherence offsets (carry analog). Must be fully reversible and public.
  3. LWM-WITNESS-01 — Emit coverage signature vectors using GWR-selected attractor and DNI-normalized divisor count at each supporting composite. Used for post-nomination structural certificate, not for primary ranking.

Each secondary experiment must be defined only after LWM-BAND-01 has produced its public freeze artifacts and a go/no-go decision.

7. PGS Object Integration (Required Frame)

Per AGENTS.md and the literal-web contract, every refinement must be expressible starting from PGS objects:

  • Ordered divisor-count field around N
  • Divisor Normalization Identity (DNI)
  • Leftmost Minimum-Divisor Rule (GWR) attractor selection
  • Chamber phase / endpoint relative positioning
  • Local gap structure between consecutive observed composites

Thread typing via GWR/DNI is the natural and contract-compliant way to define richer bands (Experiment 4 above). The first run of LWM-BAND-01 may use the simplest public proxy (log r) and treat GWR/DNI typing as an explicit follow-on variable.

8. Guardrails & Invalidated Approaches

Shape warnings (must be re-read before any code change):
• Do not re-introduce ratio-tuned candidate lists, retention caps, or depth pruning as the primary mechanism.
• Do not use known p or q to set band boundaries or window sizes.
• Do not convert a coherence score into a classical search or ranking for trial division.
• Propagation rules must not become hidden search ladders.
• All emitted public artifacts must be frozen before any audit labels are read.

Invalidated on this branch: Any claim that the web “discovers” factors without the public-before-audit contract. Any conflation of this work with Miller-Rabin, gcd, or product-closure inference.
