Locked Baseline Formula (per Codex Round 01 Answer)

The denominator for every reduction calculation is fixed for the lifetime of this contract and all measurement surfaces under it:

original_space_size(N) = count of odd positive distances d
                         with 1 <= d <= public_radius(N)

public_radius(N) = 2 ** ceil(bit_length(N) / 2)
original_space_size(N) = (public_radius(N) + 1) // 2

Reduction metrics (public, emitted in every manifest):

  • candidate_reduction_ratio = original_space_size(N) / emitted_count
  • candidate_reduction_bits = log2(original_space_size(N)) − log2(emitted_count)

If emitted_count == 0, the reduction status for that N is unresolved (not infinite reduction).

This baseline is deliberately conservative: it counts all odd positions up to the public radius and therefore does not credit the filter for excluding evens or composites that classical prefilters could also remove. The thread set never enters the denominator.

Research Frame (PGS-Native)

The runner operates exclusively on public N. It constructs candidate endpoint positions (distances) by building chains of modulus-link closures from the residues of N on a public set of small primes (threads). Each added thread that is successfully incorporated via CRT represents an additional independent link closure. The triangulation depth of a distance is the number of such simultaneous closures it satisfies. The public filter retains only those distances that achieve sufficient depth and emits a capped, ordered list. No private factor, gcd, divisibility test, or product closure is used or consulted during nomination.

Success is defined solely by post-freeze membership of the true hidden factor distance in the emitted public list. The measured win is the publicly observable reduction in the size of the candidate set that must be further examined.

Public Inputs

  • --n <N>, the semiprime (integer, bits only; no sidecar data)
  • --out-dir <path>, writable directory for the frozen artifacts
  • Policy is supplied by the locked constants inside the runner for v01 (see table below). No runtime flags that would allow hidden tuning of depth, threads, or cap.

Candidate Generation Mechanism

The mechanism is a deterministic public construction of candidate endpoint positions via successive modulus-link closures:

  1. Compute public_radius and original_space_size from N using the locked formulas above.
  2. Pre-compute, for each thread in the fixed public thread_set, the left residue N % thread and right residue (-N) % thread.
  3. Begin with the base partial solution (modulus = 2, residue = 1, depth = 1, sides containing 2).
  4. Iteratively extend each live partial solution by attempting to incorporate the next unused thread in thread-set order. Extension succeeds only when the CRT combination yields a new representative distance that is still ≤ public_radius. On success, depth is incremented and the thread is recorded on the appropriate side(s).
  5. Any completed distance whose final depth meets or exceeds min_depth is retained (after deduplication across all extension paths).
  6. Each retained distance receives the public score components defined below.
  7. Sort by the locked scoring key (descending), truncate to max_candidates, assign dense ranks starting at 1, and emit the ordered list.

No step in the above procedure performs or consults a divisibility test, gcd, primality test, or any value derived from the hidden factors. The only arithmetic is public CRT combination of residues of N and the public thread primes.

Triangulation Score Ingredients (All Public)

Primary sort key (descending): triangulation_depth

Secondary (descending): shared_thread_count (threads appearing on both left and right sides for the same distance)

Tertiary (descending): total_thread_count (left + right)

Final tie-breaker (ascending): distance (smaller distance wins)

The scoring key is fully described in every manifest and never depends on private information.

Toy-Scale Measurement Surface

A public cases/toy_corpus.jsonl (one JSON object per line containing at minimum {"N": <int>}) will be supplied and its SHA-256 recorded before any runner execution against the corpus. The corpus may contain both previously audited toys and fresh N values never used in private audits. The runner and the canonical checker must treat every entry as N-only; human labels are ignored by automation.

For each N in the corpus the exact protocol is:

  1. Run the v01 runner from N alone → produce and hash public_output.jsonl + public_manifest.json.
  2. Print the full PUBLIC_FREEZE_RECORD gate (see below).
  3. Only after the freeze record exists, invoke the canonical membership checker with the two hidden factors.
  4. Record the checker’s status.json (recovered / missed / unresolved).
  5. Emit a per-N summary row containing the public manifest fields plus the checker status (no private rank or containment fields).

Aggregate reporting across the corpus will include hit rate (fraction of N where status = recovered), median and range of candidate_reduction_ratio and candidate_reduction_bits for both recovered and missed cases, and the maximum emitted list size observed.

Forbidden Private-Factor Uses (Total Quarantine After Any Freeze)

After a PUBLIC_FREEZE_RECORD exists for any given N, the only permitted operation that reads the hidden factors is a direct invocation of the (hash-pinned) canonical membership checker. The following are forbidden regardless of filename, label, or stated purpose:

  • Private rank, score, or band-position calculations
  • Containment-interval or radius-diagnostic measurements using p or q
  • Sidecar files or visualizations that incorporate known-factor positions
  • Any re-scoring of the public list after private values are known
  • Any summary or narrative that cites private ranks or “how close” metrics

Violation triggers the standard gate message and invalidates the artifact for recovery purposes.

Pre-Implementation Compliance Certification Checklist

Before any implementation code is written against this contract, Grok must certify (in a separate review artifact) that the following hold for the proposed runner source and the toy corpus:

  1. Runner contains a literal private-token scan (p, q, known_factor, factor_distance, exact_factor_rank, target_distance all false) and prints the result.
  2. All generation logic is exhausted by the public CRT-extension description above; no hidden constants or branches derived from prior private audits.
  3. The locked v01 parameters (thread_set, min_depth=5, max_candidates=512) are the only values used for the initial campaign; they appear as immutable constants with a comment referencing this contract version.
  4. The original_space_size formula is implemented exactly as locked and is used for every manifest.
  5. The toy_corpus.jsonl (when supplied) contains only N values; the runner never reads any private or label-derived field.
  6. The canonical membership checker remains the identical pinned artifact (or a new one with new hash explicitly re-certified).
  7. No code path exists that would allow the public list to be re-ranked or filtered after private factors are known except via the canonical checker.

Only after a certified_compliant (or certified_with_required_corrections that are then applied) from Grok may the runner be written and executed against the toy corpus.

Residual Risks Acknowledged in This Contract

  • Pre-freeze oracle influence on the choice of the locked v01 parameters themselves (thread count, depth 5, cap 512). These values were selected conservatively to match the user’s stated target regime; they are now part of the public record and cannot be adjusted silently.
  • Cross-session smuggling of private measurements into the design conversation. Mitigated by requiring the full design contract (this HTML) and the pre-implementation certification to be written before any code exists.
  • Future temptation to enlarge the thread_set or lower min_depth on the same corpus after seeing hit rates. Such a change constitutes a new contract version and must be accompanied by a fresh corpus or explicit statement that prior results are invalidated for comparison.

Invalidated or Out-of-Scope for This Contract

  • Any claim that the v01 filter “factors” N or replaces classical methods. The contract measures only public list containment and cardinality reduction.
  • Private rank or “near-miss” diagnostics as recovery evidence (already ruled out by the parent PUBLIC_EVIDENCE_INTEGRITY_CONTRACT).
  • Scale claims beyond the declared toy corpus until a subsequent contract version is frozen and executed under the same gates.
  • Use of the thread set or any CRT arithmetic as a classical prefilter inside a larger hybrid system unless that system is itself placed under a new, separate public-N-only contract.

This design contract is frozen. Implementation may begin only after the pre-implementation Grok compliance certification against the checklist above. All subsequent runner executions on any N must produce the PUBLIC_FREEZE_RECORD gate before private factors are supplied. The canonical membership checker remains the sole admissible post-freeze private operation.
