Explanatory Evidence Amendment
to v01 Candidate-List Runner

Status: FROZEN AMENDMENT CONTRACT — v01.1

Parent Contract: design_contract.html (v01) in this folder
Meeting: candidate-list-search-space-reduction-runner — Explanatory Evidence Amendment
Scope: Public-only diagnostic fields for the existing toy v01 corpus. No change to recovery criteria, cap, depth threshold, thread set, or nomination logic.

Objective (Public Only)

Add the minimum public aggregate statistics, computed entirely during the N-only public CRT construction phase, that allow post-execution analysis to distinguish the five failure modes listed in the meeting prompt using only data visible before the canonical membership audit.

Recovery surface, emitted list contents, and hit-rate definition remain identical to v01. The 3/10 result on the declared toy corpus is the baseline; this amendment only supplies explanatory descriptors for that same surface.

Exact Fields Added to public_manifest.json

All fields below are derived strictly from the candidates dictionary (depth ≥ 5 distances) after the public extend_assignments recursion completes and before any sort or truncation. They are written into the manifest inside write_outputs under the same PUBLIC_FREEZE_RECORD discipline.

FieldTypeDefinition (public computation)Purpose
pre_cap_qualified_count integer len(candidates) after all qualifying distances have been inserted by add_candidate Direct measure of filter density. Small value with cap inactive → “filter too sparse”.
max_observed_triangulation_depth integer maximum triangulation_depth value among the qualified set (0 if empty) Upper end of the public signal strength on this N.
depth_counts_pre_cap object {str(d): count} for every exact depth d ≥ min_depth present in the qualified set Full public distribution of closure strength before the cap is applied.
cap_active boolean pre_cap_qualified_count > max_candidates Immediate indicator of cap saturation for this N.
emitted_depth_counts object identical shape to depth_counts_pre_cap but counted only over the final emitted rows (after cap) Allows direct comparison of pre-cap mass vs. what the cap retained; computable from public_output but recorded for audit convenience.
cutoff_triangulation_depth integer triangulation_depth of the lowest-ranked row in the emitted list (or 0 if empty) When cap_active, shows whether the cap is still cutting at high depth (concentration) or has already reached the min_depth floor.
pre_cap_to_emitted_ratio number or null pre_cap_qualified_count / emitted_count when emitted_count > 0, else null Quantifies how much of the qualified set was discarded by the cap (scale-pressure signal).

These seven fields are the complete addition. No other public or private values are introduced into the manifest or the public_output.jsonl rows.

Optional Public Sidecar — None Required

All explanatory aggregates fit inside the existing public_manifest.json. No new sidecar file is created by this amendment. The public_output.jsonl format and content are unchanged (identical row schema and ordering for any given N under the locked v01 nomination rules).

Unchanged Private-Audit Boundary

  • The canonical membership checker (audit_behavior: "canonical_membership_only") remains the sole operation permitted to read hidden factors after the PUBLIC_FREEZE_RECORD is emitted.
  • status.json retains its current schema (status, recovered_factor or null, p_emitted, q_emitted).
  • No private rank, containment, band position, or “how close” value is ever written to any artifact under this amendment.
  • The private_token_scan and PUBLIC_FREEZE_RECORD gate are executed exactly as in v01 before the checker is invoked.
  • Recovery language remains strictly “the frozen public list contained the true distance or it did not.”

Rerun Protocol for the Current Toy Corpus

  1. Place the amended runner source (named thread_triangulation_v01_1_runner.py or equivalent) in the meeting directory. The nomination logic (CRT extension, add_candidate, scoring key, [:MAX_CANDIDATES] truncation) must be identical to the certified v01 runner; only the collection of the seven aggregates above is added before the slice.
  2. Execute the amended runner against the identical public cases/toy_corpus.jsonl (SHA unchanged) using the same per-case command pattern, directing output to a fresh tree: 
    output/toy_v01_amended/<case_id>/public/{public_manifest.json, public_output.jsonl}
output/toy_v01_amended/<case_id>/audit/status.json
  3. For each N: the runner prints an updated PUBLIC_FREEZE_RECORD that includes the seven new manifest fields and their values. Only after the gate completes is the canonical membership checker invoked (reproducing the same recovered/missed labels as v01 because the emitted list is unchanged).
  4. Aggregation script (or manual) produces output/toy_v01_amended/summary.json and summary.md containing the original summary rows plus the seven new columns for every case.
  5. The original v01 output tree is left untouched for baseline comparison.

Findings Reporting Requirements (No Private Diagnostics)

The post-execution findings report (to be written after the amended run and canonical re-check) must obey the following constraints:

  • Every numeric claim is taken from the public manifests (new fields) or the canonical status.json files only.
  • Recovered vs. missed cases are compared solely by bucketed aggregates of the seven public fields (e.g., median and range of pre_cap_qualified_count, distribution of max_observed_triangulation_depth, fraction of cases with cap_active true in each bucket, visual or textual overlap of the depth-count histograms).
  • Each of the five desired evidence modes is addressed with a direct public observable:
    • filter too sparse: cases where pre_cap_qualified_count is low (e.g. < 64) and cap_active = false
    • cap saturation: cases where cap_active = true and pre_cap_qualified_count ≫ 512
    • score concentration: among cap-active cases, the fraction of emitted rows that sit at max_observed_triangulation_depth or the gap between cutoff_triangulation_depth and max_observed_triangulation_depth
    • weak differential signal: quantitative or qualitative statement on whether the distributions of pre_cap_qualified_count and max_observed_triangulation_depth for the three recovered N values are clearly separated from or overlap heavily with the seven missed N values
    • scale pressure: trend of pre_cap_to_emitted_ratio (or raw pre_cap_qualified_count) versus N_bits across the corpus, independent of recovery status
  • No sentence may reference the private rank, position, or containment status of any true factor distance. The only per-N private-derived label allowed is the binary “recovered” / “missed” supplied by the canonical checker after the freeze gate.
  • The report must state the exact limitation: “These public descriptors explain the shape of the filter’s output surface on the declared toy corpus; they do not explain why any individual missed N’s factor distance failed to qualify.”

Explicit Prohibitions (Reaffirmed)

  • Do not add, compute, or emit any field whose value requires knowledge of p or q (rank among qualified, distance to nearest qualified, band of the true factor, etc.).
  • Do not alter the emitted candidate list or the recovery decision procedure.
  • Do not introduce randomness, tunable parameters, or post-freeze re-scoring paths.
  • Do not change the toy_corpus.jsonl or claim the amendment validates a new parameter set for future use.

Implementation Notes for the Amended Runner

The minimal diff from the certified v01 source is:

  1. Inside nominate (or immediately after the call to extend_assignments inside write_outputs), before the sorted + slice, capture: 
    qualified = list(candidates.values())
pre_cap = len(qualified)
if pre_cap == 0:
    max_d = 0
    depth_hist = {}
else:
    max_d = max(r["triangulation_depth"] for r in qualified)
    depth_hist = {}
    for r in qualified:
        d = r["triangulation_depth"]
        depth_hist[d] = depth_hist.get(d, 0) + 1
  2. After truncation to rows, compute the emitted histogram and cutoff depth from rows using the same Counter pattern.
  3. Insert the seven fields into the manifest dict exactly as named above (JSON numbers, booleans, and object with string keys for depths).
  4. Update the printed PUBLIC_FREEZE_RECORD block and the final manifest echo to include the new keys.
  5. Leave private_token_labels, THREAD_SET, MIN_DEPTH, MAX_CANDIDATES, scoring key, and all CRT logic untouched.

The resulting public_output.jsonl for every N in the toy corpus must be identical (same SHA-256) to the v01 artifact when the only difference is the added manifest fields.

This amendment contract is frozen. It adds only public diagnostic aggregates to the v01 surface. The recovery experiment, the 3/10 baseline, and the public/private quarantine are unchanged. Implementation of the v01.1 runner and the subsequent explanatory findings report may proceed only after Grok certification against the checklist above.
