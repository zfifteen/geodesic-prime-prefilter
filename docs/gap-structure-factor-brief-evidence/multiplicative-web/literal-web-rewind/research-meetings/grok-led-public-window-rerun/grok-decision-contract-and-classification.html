Decision record and corrected experiment contract — 19 May 2026

Grok is the lead decision-maker. This document ratifies the repaired public-window experiment, records the first policy tested under the strict separation contract, presents the measured rerun results on toy and continuation semiprimes, and issues the final classification.

All prior Codex scaling claims that reached “255-bit semiprime” are INVALIDATED. Hidden factor data (p, q, min(p, q)) leaked into radius selection, candidate/hole construction, and success definitions. The measurement was answer-aware scaffolding, not public inference.

1. Corrected Public Experiment Contract (Non-Negotiable)

Public Runner — Inputs and Guarantees

  • Receives only the integer N (the semiprime) and a fixed set of public policy parameters (R, threads, top_k) that are either compile-time constants or computed solely from the public bit-length of N.
  • Never receives, stores, or uses p, q, min(p, q), gcd(N, ·), factorint, isprime, nextprime, sqrt(N) walks, or any secret-derived radius/offset.
  • Generates nominated offsets exclusively from the arithmetic progressions t ≡ −N (mod r) for each public small prime r in the threads tuple, truncated at the public radius R.
  • Applies a deterministic “first thread” rule and a public sort key (in v1: ascending |offset| then offset) to produce an ordered list.
  • Emits a frozen JSON record containing only N, N_bits, policy name, parameters, the top_k nominated items (offset, first_thread, value), and cost counters. The record carries the marker "public_only": true.

Audit Runner — Post-Freeze Only

  • May construct N = p × q for benchmark cases and may read the frozen public JSON.
  • May re-execute the identical public nomination function on the same N to obtain reproducible full ordered lists for rank lookup.
  • Computes ranks, hits-in-top-k, and classification labels after the public artifact is written.
  • Writes audit-only files (containing p/q) in a separate tree; never mutates or feeds back into the public generator.

Any script that sets radius from min(p, q), builds hole sets via direct p/q offsets before nomination, or defines “success” by counting secret hits inside an answer-aware candidate pool violates this contract and is disqualified as evidence.

2. Policy Tested First — first_thread_proximity_v1

This is the exact rule described in the opening brief as the “last intended simple method” and the first policy Grok elects to run under the repaired contract.

threads = (2, 3, 5)
R       = 1 << 18          # 262144 — fixed public compute budget
top_k   = 20

for each r in threads:
    res = (−N) % r
    generate all t in [−R, R] \ {0} with t ≡ res (mod r)
    assign each such t its smallest r as “first_thread”
deduplicate (first-seen / smallest-r wins)
sort by (abs(offset), offset)
emit the first top_k items

The public runner (public_window_runner.py) implements exactly this logic and nothing more. The private audit (private_audit.py) calls the public function with N only, then scores the secret offsets post-freeze.

4. Plain Classification

ACCEPTED BOUNDARY MEASUREMENT — prior scale-up claims INVALIDATED.

The first public-window policy (2-3-5 first-thread proximity inside a fixed feasible R) does not place the hidden-factor offsets (p or q) inside the reported top-20 for any tested case. When the window is large enough to contain the factor offset, the actual p/q locations are ranked hundreds to hundreds-of-thousands deep because the proximity sort is dominated by the dense population of small-offset multiples of 2, 3, and 5.

When the smaller factor exceeds the public R, the window cannot reach the offset at all.

Therefore the 255-bit (and all larger) “scaling through a semiprime” results produced by the earlier sparse_web_first_coverage_scale.py / sparse_web_scaling_ladder.py / ratio-window scripts are methodologically invalid. They measured answer-aware scaffolding, not blind public recovery.

This is not an implementation bug in the new runners. The runners satisfy the contract: public sees only N; audit scores after freeze. The outcome is a clean boundary datum about the limitations of ultra-sparse proximity nomination.

5. Implications for PGS-Native Cryptologic Work

Any enumeration window whose radius is a feasible public function of N (poly-log or 2^24–2^30 at most) is orders of magnitude smaller than a 127-bit factor. Consequently, no “scan around N and rank holes” rule can ever directly nominate the true factor offset once the semiprime leaves the toy regime.

Recovering a large secret factor from N alone under a strict public contract therefore requires a non-enumerative, constructive rule:

  • one that emits a short list of candidate offsets (or a direct candidate for p) using only N and public constants;
  • without ever walking a radius ≥ the secret factor size;
  • without classical oracles (gcd, factorint, primality tests) in the inference path.

This is precisely the frame required by the project contract for cryptology-adjacent PGS research:

locked PGS endpoint chain → floor transport through modulus → reciprocal endpoint closure → modulus-link residual → structural certificate or unresolved state

The literal-web / sparse-window experiments remain valuable for calibrating what the raw multiplicative web looks like under public constraints, but they cannot be promoted to large-scale factor recovery evidence. Future claims in this subfolder must either (a) exhibit a genuine constructive public generator meeting the bullet list above, or (b) be labeled explicitly as boundary measurements of window-based heuristics.

7. Next-Step Guidance (Grok Decision)

The v1 proximity policy has been tested and classified. The meeting folder now contains a reusable, auditable public+private pair that any future policy (e.g. v2 support-count ranking over a broader public small-prime set inside a still-feasible R) can reuse by editing only files inside this tree and re-invoking the separated runners.

Because a feasible window can never reach cryptographic-scale factor offsets, any serious continuation of the public-factor-inference line must eventually migrate out of the “enumerate holes around N” frame and into the PGS-native mechanisms already under active research (endpoint chains, modulus links, reciprocal closure, structural certificates). The present rerun closes the loop on the simple sparse-thread proximity proposal.
