# Rewind To The Literal Multiplicative Web

## Active Finding

The active object is the literal web of factor threads around a semiprime `N`.

For nearby composites `N + t`, visible factors create threads across the offset line. When direct rows containing the audit factors are held out, the remaining public rows still point to missing offsets. In the original toy surface, those missing offsets were dominated by the held-out factor-distance rows.

This is the mechanism to preserve:

1. choose `N`;
2. choose a public window rule;
3. factor visible composites around `N`;
4. record public factor threads;
5. hold out direct `p` and `q` rows for audit only;
6. score missing offsets by literal thread support;
7. report success only when the public output emits `p` or `q` before audit labels are read.

## Parked Detour

The ratio candidate-list branch is parked as an invalidated active path.

That branch replaced the literal web with a synthetic public candidate generator, ratio retention controls, and scoring layers. The audited iteration series removed hidden-factor leakage and hard caps, but the corrected runner produced `0/10` recovery across the tested toy corpus through iteration 05. The strongest failure case emitted the full qualified public set under that mechanism and still missed.

The measured lesson is narrow and useful: tuning those ratios did not recover the original mechanism. The negative result belongs to the candidate-list branch, not to the literal multiplicative web.

## Current Boundary

The next runner must stay inside the literal web:

- nearby composites around `N`;
- visible factor threads from those composites;
- missing offset holes;
- thread support as the primary evidence;
- public output before audit;
- known `p` and `q` used only for benchmark construction, holdout labels, and final scoring.

The next runner must avoid:

- residue certificates;
- CRT candidate generation;
- modular ranking;
- candidate containment as success;
- private ranks as success;
- using known `p` or `q` to set the window;
- testing candidates against `N`;
- product closure;
- divisibility gates against candidate factors;
- prime streams, root walks, or classical factor-search loops.

## Next Experiment Shape

The next experiment should be a small successor to `literal_web_hole_trace.py`.

The runner should accept only public case inputs and public window/thread settings. It should emit the raw visible rows, the thread table, the supported missing offsets, and a short public candidate list. Audit then reads known `p` and `q` after the public files are frozen.

The first target is not scale. The first target is a clean public recovery contract at toy scale:

```text
public web evidence -> emitted candidate offsets -> audit membership
```

Once that clean contract recovers one factor on the toy surface, scaling changes only `N` and public ratios. A failure at larger scale then means the literal web rule needs a better public window or thread-selection ratio, not an added inference subsystem.
