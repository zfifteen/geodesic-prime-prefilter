Meeting: Reciprocal Shadow Correct Experiment  |  Lead: Grok  |  Facilitator/Recorder: Codex  |  Created: 2026-05-19

Lead Finding (Plain English)

The corrected experiment tests a single, narrow question: does the local multiplicative web around a public semiprime N, using only its held-out divisor threads, emit a compact residue certificate (a short list of admissible lower-endpoint residue classes modulo a product of thread factors) such that the hidden lower factor p lies inside one of the nominated classes, while the identical procedure run on a rotated-offset control web does not nominate p's class at the same cardinality or rank?

This is a structural-certificate experiment, not a numeric factor search. The generator never produces or walks candidate integers. It emits only residue classes derived from reciprocal transport and consistency closure on the thread list. Numeric representatives appear only at final audit to test class membership of the known p (or q). The first valid surface therefore measures whether the web itself nominates the correct residue class, not whether a walk eventually lands on the factor.

Reciprocal Residue Closure Invariant (Codex Round 1 - exact)

Definition sketch: Given the held-out local web around public N, construct a finite residue certificate over the thread factors. A lower endpoint class is admissible only if its transported partner residues produce a stable divisor-count shadow across the same offset-indexed web under all offset-preserving controls.

The generator must emit residue classes or endpoint classes directly from this closure calculation, not from an interval of numeric candidates. Numeric representatives are introduced only after the certificate exists, and only to audit whether the hidden factor lies in the emitted class.

Hierarchy (Codex): modulus-link closure supplies the transport plane; reciprocal residue closure supplies the missing selector; endpoint-chain traversal audits or refines the selected endpoint class.

This invariant is unresolved, not proved. The experiment design below operationalizes one concrete, auditable version for the first surface only.

1. The Object Being Measured

The object is the reciprocal residue closure selector operating on the public local multiplicative web (held-out divisor threads of N +/- radius). The measurement asks whether this selector, by itself, emits a compact residue certificate whose classes contain the hidden lower endpoint under the true offset-to-factor pairing and do not contain it (or rank it materially worse) under offset-preserving controls.

3. Candidate-Generation / Certificate Mechanism (Residue Certificate Only)

Operationalization for v1 probe (concrete, from Codex invariant + meeting synthesis):

  1. Build held-out thread list exactly as in reciprocal_shadow_vote_probe.py (composite_rows, filter rows containing p or q).
  2. Select the 4 distinct r values with the highest thread degree (most appearances) in the held-out list. Let M = product of those 4 r's. (If M > 5 000 000 for any case in the first surface, fall back to the 3 highest-degree r's.)
  3. For every residue a = 0 ... M-1:
    • For each of the 4 r's, collect the set of all b = (-t * inv(a mod r, r)) mod r predicted by every thread whose factor is that r.
    • If any r has more than one distinct b, the predictions conflict inside that modulus - discard a.
    • Now a single b_r per r. Attempt incremental CRT merge across the 4 (r, b_r) pairs to find whether a single partner class y mod M exists that satisfies all four simultaneously.
    • If the CRT merge succeeds with zero conflicts, a is admissible. Its closure score = (total threads whose r is one of the 4) / (total threads using those r's). Record the implied y mod M as part of the class record.
  4. The emitted residue certificate C is the list of all admissible a (with their closure scores and the recovered y). Sort by descending closure score; ties broken by smallest a.
  5. Exactly the same procedure is run on the rotated-offset control thread list to produce C_rot.

No integer candidate is ever generated. The only numbers that ever appear are the residues a mod M and the merged y mod M. Numeric search or sieving is forbidden until after C is emitted and only for the final membership audit on known p.

4. Exact Success Condition

  • For every case in the surface: p % M appears in the admissible list of the true-web certificate C.
  • Its rank by closure score inside C is 1 (or <= 2 if the surface contains documented ties).
  • Certificate cardinality |C| <= 64 for all cases in the first surface (the bound may be raised only by explicit amendment).
  • On the rotated-offset control web for the same N: either p % M does not appear in C_rot, or its rank in C_rot is worse than |C_rot| / 2, or |C_rot| is materially larger than |C| while still containing p.
  • Aggregate: at least 14 / 16 cases on the original 16-case surface satisfy the above four bullets simultaneously.

5. Exact Falsification Condition

The experiment is falsified for the first surface if any of the following occur:

  • For 3 or more cases, p % M is absent from the true-web C, or its rank inside C is > 3.
  • The rotated control C_rot contains p % M at rank 1 with |C_rot| comparable to |C| on 3 or more cases (the signal is not destroyed by offset rotation).
  • |C| > 64 on any case while still being the only way to include p (certificate not compact).
  • The generator code (after build_case returns) contains any reference to the numeric values of p or q, or constructs any integer interval whose placement depends on secret factors.

Appendix B - Acceptance Checklist (12 Items)

  • Generator source (after the single build_case call) contains zero references to p or q values or identifiers.
  • No integer interval, prime stream, or segmented sieve is constructed whose bounds depend on anything except the thread list and the chosen r's for M.
  • M is computed solely from the 4 (or 3) highest-degree r's in the held-out threads; no secret data enters the selection.
  • Every admissible a in C is produced by the conflict-check + CRT-merge procedure; no other numeric search is performed.
  • The identical closure procedure is run on the rotated-offset thread list and its C_rot is recorded.
  • Success/falsification numbers are computed only from membership of (p % M) in C vs. C_rot and the ranks by closure score.
  • At least 4 of the 16 + 2 new cases have p < 0.6 x sqrtN (natural ratios, no 97/100 bias).
  • |C| <= 64 on every case that passes the membership test.
  • Runtime log (printed or written) lists every arithmetic step that contributed an a to C; the log is free of N-division or gcd(N,*) calls.
  • Rotated-control and synthetic-random control both executed and reported; neither nominates p at equal rank/cardinality on more than 2 cases.
  • Implementation witness has read this HTML in full and confirms the 7 sections + 2 appendices match the code.
  • Raw output files (summary.json, certificate.jsonl, summary.md) are committed alongside the probe script before any interpretive claim is published.

Meeting Deliverable - Status

Negotiated deliverable: This single self-contained HTML file is the complete, implementation-ready contract. It incorporates the Codex Round 1 answer verbatim (the Reciprocal Residue Closure Invariant and the weaker structural-certificate target) and supplies the missing concrete operationalization required for a v1 probe that cannot re-introduce walk or hidden-factor leakage.

Once the implementation witness (Codex) confirms the checklist can be executed against the written probe, the first corrected surface run may begin. No further design rounds are required unless the v1 run itself reveals an ambiguity in the closure procedure.

The Reciprocal Residue Closure Invariant remains unresolved. The HTML records one auditable operationalization for the first surface only; stronger or more general statements are future work.

PGS-native frame enforced throughout: locked local web -> reciprocal transport (b = (-t*inv(a,r)) mod r) -> modulus-link closure (CRT merge) -> reciprocal residue closure (conflict filter + consistency) -> structural certificate (admissible a list) -> audit membership of hidden endpoint. Classical numeric search is downstream of the certificate and is used only for final verification on known test cases.
