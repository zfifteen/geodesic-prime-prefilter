Residue Certificate V2 Public Selector Contract

Meeting: Residue-Certificate Public Selector | Created: 2026-05-19 | Status: hypothesis contract

Lead Finding

The first cross-audited residue-certificate experiment produced a clean boundary measurement: the true local multiplicative web emitted a non-empty certificate while rotated and deterministic synthetic controls emitted empty certificates, but the true certificate collapsed to the 48 residues coprime to 210. V2 keeps that audited certificate layer unchanged and adds one public ranking rule over the 48 residues using the divisor-count field and the leftmost minimum-divisor witness inside the held-out web.

This contract defines a ranking hypothesis. It does not claim factor discovery, proof, or accepted evidence until the same 20-case surface is executed and cross-audited.

2. V2 Selector Object

The V2 object is a public ranking rule over the V1 certificate. It does not change how the V1 certificate is generated. It reads one additional public field: the ordered divisor-count field of the held-out composite rows around N.

PGS-Native Frame

held-out local web -> divisor-count field -> leftmost minimum-divisor witness -> reciprocal transport deviation -> ranked structural certificate -> final membership audit of known p % M.

5. V1 Certificate Layer, Frozen

For each case, build the held-out thread list exactly as in the V1 cross-audited experiment. Select the four highest-degree thread factors. On the measured surface this selects [2, 3, 5, 7] and M = 210.

For every residue a in 0..M-1, compute per-factor reciprocal predictions:

b_r = (-offset * inverse(a mod r)) mod r

If every selected r has one consistent b_r, merge those congruences by CRT and emit a into certificate C. This V1 layer remains unchanged.

6. GWR Witness Extraction

After the V1 certificate exists, extract one public witness from the held-out divisor-count field.

  1. Sort held-out rows by offset ascending.
  2. Let d_min be the minimum divisor_count among held-out rows.
  3. Let g be the first row in ascending offset order with divisor_count == d_min.
  4. Let t_g be the offset of g. This is the primary leftmost minimum-divisor witness.

Support Window

The support window is used only as a secondary tie-break.

  • Left support: the nearest row with offset < t_g and divisor_count <= d_min + 2, if one exists.
  • Right support: the nearest row with offset > t_g and divisor_count <= d_min + 2, if one exists.
  • The support window therefore contains 0, 1, or 2 rows.

7. V2 Deviation Formula

For each admissible a in the V1 certificate, compute the modular inverse of a modulo M. This inverse exists because every V1 member is coprime to M.

inv_a = inverse(a mod M)
d_primary = (t_g * inv_a) mod M
dev_primary = min(d_primary, M - d_primary)

For each support-row offset t_s:

d_s = (t_s * inv_a) mod M
dev_s = min(d_s, M - d_s)

The secondary score is parameter-free:

support_score = sum(dev_s for each support row)

The structural ranking key is:

(dev_primary, support_score)

The reporting order may append a as a deterministic final tie-break:

(dev_primary, support_score, a)

A case is not accepted if the true member reaches rank 1 only because of the final a tie-break. Accepted evidence requires the true member to be the unique winner by the structural keys (dev_primary, support_score).

  5. GWR witness extraction matches Section 6 exactly.
  6. Support window matches Section 6 exactly and contains at most one qualifying neighbor on each side.
  7. V2 deviation arithmetic uses only a, M, t_g, support offsets, and held-out row data.

  9. True, rotated, and deterministic synthetic controls all execute.
  10. Runtime logs show every inverse, multiplication, modular reduction, support score, and ranking key that contributes to a nominee.

  13. Raw outputs exist before any interpretive claim is published.
