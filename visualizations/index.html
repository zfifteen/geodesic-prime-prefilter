Working principles

  • PGS-native first. Start from ordered gap state, divisor-count field, GWR, DNI, chambers, certificates, or unresolved residual state.
  • Status separation. Theorem, measured, audit, hypothesis, unresolved, invalidated, mixed, editorial, and legacy stay distinct. Captions name the regime.
  • No claim inflation. Avoid verified/validated language without an executed 10^18 program surface. Scoreboards that mirror published aggregates must say so.
  • Catalog for durable science demos. Promote durable figures into library/entries/; keep one-offs out of the gallery until they carry status metadata.
  • Classical helpers only as labeled pedagogy or audit. Teaching divisor counts and legacy chapter art are not generator inference.

Regenerate the gallery

visualizations/library/.venv/bin/python visualizations/scripts/lint_catalog.py
visualizations/library/.venv/bin/python visualizations/scripts/run_all_demos.py
visualizations/library/.venv/bin/python visualizations/scripts/build_gallery.py
open visualizations/gallery/index.html

Always use the library venv Python for all three steps. Demo output is written to library/out/; the gallery copies PNGs into gallery/assets/ as a build product.

Add a durable demo

  1. Create library/entries/<id>/ with entry.json, demo.py, and caption.md.
  2. Register <id> in library/catalog.json.
  3. Caption order: observable object → mechanism → project term → status → limits.
  4. Run lint, demos, and gallery build. Open the gallery entry page and check the status chip and regime text.
