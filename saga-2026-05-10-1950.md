## Codex Analysis

The strongest supported conclusion is that the next goal-supporting task is not to implement resolver logic. It is to build a narrow deterministic sidecar that freezes the current public frontier state, anatomizes the two non-strict live rows, pre-registers one public normalized frontier dominance invariant derived only from the strict d=4 collapse path, and reports `resolved=true` only when every live row is eliminated by that invariant.

The plan is:

1. Freeze the public state in an input manifest:
   - 202 ledger-effective survivors.
   - 50 strict d=4 frontier candidates.
   - 50 strict candidates collapsed by strict d=4 trace.
   - 2 non-strict live rows after normalized frontier sweep.
   - forbidden mechanisms list.

2. Produce `live_rows_audit.json` from public PGS fields only:
   - row identity labels already present in the story rows;
   - public normalized frontier coordinates;
   - strict-collapse carrier labels;
   - survivor reason;
   - blocker, survivor, or recursive-collapse classification;
   - no factors, divisibility, gcd, product closure, primality, or audit labels.

3. Pre-register exactly one candidate invariant:
   - `Normalized Frontier Dominance Invariant`;
   - derived only from public strict d=4 collapse trace and public normalized frontier coordinates;
   - no thresholds fitted from the two live holdout rows;
   - no bit-size, rung ID, row ID, endpoint-budget, or fallback branch.

4. Implement the sidecar experiment:
   - suggested path: `research/06-cryptology-rsa/experiments/rsa/v2/normalized_frontier_holdout_closure.py`;
   - load the frozen manifest and current artifacts;
   - replay strict d=4 collapse and confirm 50 of 50 strict candidates collapse;
   - build the dominance witness from public strict-collapse structure;
   - apply the frozen rule to every remaining live row;
   - emit row-level before/after records.

5. Add a public checker:
   - verify each elimination references the pre-registered invariant;
   - verify no forbidden mechanism appears in inputs, output fields, or code path;
   - verify `resolved` is false unless `live_after == 0`;
   - verify row order does not change the result.

6. Falsification tests:
   - a survivor remains after the invariant: unresolved;
   - 40-bit and 50-bit rows require different logic: invalid;
   - a threshold is tuned after seeing holdout rows: invalid;
   - the rule depends on bit size, rung ID, endpoint budget, hidden factors, divisibility, gcd, product closure, primality, or fallback: invalid;
   - strict d=4 trace is not replayed at 50 of 50: invalid;
   - toy closure passes but cannot be expressed as a public normalized frontier invariant: invalid.

7. Scale back to 40-bit only after the sidecar passes:
   - freeze the invariant implementation;
   - freeze the manifest and checker;
   - replay unchanged on the 40-bit RSA v2 ladder row;
   - if any live row remains, mark unresolved and write the blocker.

Resolver logic may be touched only when a standalone, frozen, public PGS-native normalized frontier invariant eliminates every live survivor on the toy closure surface, passes all falsification tests, emits row-level artifacts, and replays unchanged on the 40-bit RSA v2 ladder with zero live survivors. Even then, the resolver change is limited to calling the already-frozen invariant as a named public rule. No tuning, new branches, per-rung clauses, or fallback paths.

Remaining unresolved questions:

- Whether a public normalized frontier dominance invariant actually exists.
- Whether the two non-strict live rows share one structural reason or represent two distinct blockers.
- Whether the existing story-row artifacts expose enough public normalized coordinates to derive the invariant without adding an invalid audit dependency.
