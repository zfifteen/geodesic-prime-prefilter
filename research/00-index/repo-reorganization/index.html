Resolved Decisions

Question Decision Reason
Permanent research root Use top-level research/. docs/research/ currently mixes documentation with research state. A top-level root makes research a first-class corpus and lets each chapter contain docs, scripts, outputs, and audit evidence together.
Production generator code Keep production code in src/, tests/, and benchmarks/. The generator is a repo-wide implementation surface, not only a research episode. The 01-generator chapter points to production files and owns research-specific evidence, not the production source tree.
Top-level output/ Dissolve it into chapter outputs/ folders, with archive/ labels for stale or superseded evidence. Output provenance belongs beside the script, question, and status note that produced it. A global output dump hides whether a result is headline evidence, stale scratch, invalidated, or unresolved.
Old branch names Preserve branch names in chapter metadata when they explain provenance. Branches encode the history of research episodes. They should not define the folder structure, but they are useful evidence for where a result came from.
Compatibility pointers Use short README pointers, not symlinks. Plain files are easier to audit and survive GitHub, local browsing, and future tooling without path-resolution surprises.

Chapter Contract

Every chapter gets a short README.md with the same sections.

Section Required Content
Object The concrete PGS object being studied.
Invariant Or Rule The relevant PGS invariant, theorem, measured rule, or unresolved candidate.
Proof Status Direct pointer to PROOF.md when proved; otherwise explicit non-proof status.
Measured Evidence Exact output paths and tested regimes.
Audit Status Whether output was independently checked, and by what script or sidecar.
Invalidated Rules Named failed rules and the artifact that falsified them.
Unresolved State The current blocker, survivor set, or missing invariant.
Reproduce The smallest deterministic command that regenerates the headline evidence.
Provenance Original branch names, old paths, and migration commit when those facts help continuity.

Migration Rules

No Big-Bang Move

Move one research family at a time. Each move must preserve a working entrypoint, exact output provenance, and a compatibility pointer from the old path when needed.

  1. Create the chapter folder and README first.
  2. Move only files belonging to that chapter.
  3. Keep generated outputs with the scripts that produced them when the outputs are part of the evidence.
  4. Leave large or obsolete scratch outputs in an archived area only after their status is identified.
  5. Update imports, command examples, and documentation links in the same commit as each move.
  6. Run the smallest deterministic validation for that chapter before moving to the next one.
  7. Update START_HERE.md after each completed chapter migration.

Move Mechanics

  • Use git mv for every tracked relocation.
  • Do not copy old files into new locations unless the old copy is explicitly marked as a compatibility pointer.
  • Do not rename concepts while moving files. Terminology changes belong in separate commits.
  • Do not combine family migrations in one commit unless the families already share scripts and outputs.
  • Keep LF line endings in all generated Markdown, JSONL, CSV, and text files.

Status Vocabulary

Chapter READMEs and index tables should use these exact status labels.

Label Meaning
proved Universal theorem under the hypotheses stated in PROOF.md or another explicit proof artifact.
measured Finite empirical or computational result with exact regime and reproducible output path.
audited Generated output independently checked by a separate validation path.
hypothesis Live explanatory candidate not proved and not falsified.
unresolved Open blocker, survivor, missing invariant, or non-closing rule.
invalidated Rule or conjecture falsified by a named artifact.
archived Historical output retained for provenance, not active evidence.

Acceptance Criteria

  • A new reader can identify every active research family from one index.
  • Every migrated chapter separates theorem status, measured result, audit status, hypothesis, invalidated rule, and unresolved state.
  • No proved theorem wording is weakened during relocation.
  • No unresolved result is made to sound solved by folder placement or summary language.
  • Every moved script has either a passing validation command or an explicit stale/archived label.
  • Root authority files remain stable and easy to find.
