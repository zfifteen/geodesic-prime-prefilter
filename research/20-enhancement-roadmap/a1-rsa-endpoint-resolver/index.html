Enhancement A1 · Requirements specification

Mature the deterministic PGS-native RSA modulus endpoint resolver

Build a general engine that, given a public RSA modulus (or family of moduli), traverses locked endpoint chains using only PGS objects and rules, emits a public structural certificate when invariants close to an oriented endpoint class, and emits an explicit diagnosable unresolved state when they do not. Scale the engine so 256-bit, 512-bit, and 1024-bit+ cases are routine instrumentation targets, not one-off demos.

ID: A1 counsel winner 2026-07 measured: small rungs unresolved residuals exist crypto-scale engine: target implementation track
Claim boundary (read first). A1 does not claim to factor RSA, break cryptography, or prove a new universal factorization theorem. It claims to read and certify deterministic endpoint structure that moduli expose under DNI zero-excess primes and the proved GWR maximizer. Classical factor confirmation is audit only, after inference, and never chooses the endpoint class.

1. Observable object (plain language)

Start from a public modulus N. Orient around isqrt(N) only as a side separator, not as a candidate chamber. Walk previous public endpoints on the lower side. At each step, build a chamber-reset certificate (selected carrier, lock, threat, deadline, signature). Transport the oriented coordinate by floor(N / x). Build the opposite-side certificate. Test reciprocal closure and GWR-carrier alignment. When the structure closes, emit a public endpoint class plus certificate. When it does not, emit unresolved with a residual class and full diagnostic trace.

public N → endpoint chain → reset certificate → floor(N/x) → reciprocal pair → class or unresolved

2. PGS-native frame (required first frame)

locked PGS endpoint chain
  -> floor transport through modulus
  -> reciprocal endpoint closure
  -> GWR-selected carrier transport closure
  -> modulus-link residual
  -> structural certificate OR unresolved state

Upstream theorems used as foundation (not re-proved here): direct next-prime rule, GWR interior maximizer, universal bounded compression / Prime-Square Proximity as stated in PROOF.md. A1 implementation status is separate from those theorem statuses.

3. Goals and non-goals

Goals

  • Generalize RSA v2 reciprocal PGSPG instrumentation into a versioned resolver track (working name: endpoint-resolver-v3) with one algorithm contract across bit lengths.
  • Make GWR-selected carrier transport closure explicit predicates, not ad-hoc numeric alignment bounds alone.
  • Emit portable structural certificates with a standalone verifier.
  • Emit honest unresolved states with a stable residual taxonomy.
  • Produce public resolved/unresolved corpora at 128, 256, 512, and 1024-bit targets (as implementation evidence, not theorem claims).
  • Feed internal gap populations into square-branch, state-budget, gap-type, and falsification pipelines.

Non-goals

  • Claiming factorization of production RSA moduli.
  • Using Miller-Rabin, trial division, sieves, gcd, product closure, or factor APIs inside inference.
  • Changing generator stream contract {"p","q"} or downgrading proved theorems.
  • Replacing audit with inference or inference with audit.
  • Solving RH, PNT, or classical Cramér gap-width formulations as side effects.

5. Current baseline (RSA v2)

Live workbench: research/06-cryptology-rsa/experiments/live-solver/rsa-v2/. Inference shape: unified transported certificate chain. Inputs are public ladder fixtures only (no audit factors in inference).

Stages (preserve semantics unless A1 explicitly supersedes)

  1. Public orientation: compute isqrt(N) as side separator only.
  2. Initial lower anchor: previous public endpoint before isqrt(N) (step zero of one chain).
  3. Uniform chain state: derive PGSPG chamber-reset certificate; choose oriented transport coordinate x (reset endpoint if still on lower side, else anchor).
  4. Floor transport: y = floor(N / x).
  5. Upper certificate: previous public endpoint before y; derive certificate.
  6. Closure predicates: strict reset closure first; deadline-signature correction second.
  7. Emit: endpoint class states or unresolved residual states per metrics contract.

Known measured / unresolved anchors (do not upgrade)

  • Smaller bit rungs have public resolved endpoint-class examples on measured surfaces.
  • Carrier-misalignment style residuals (e.g. 50-bit-class cases) remain honest unresolved.
  • Grammar / transported-story tracks are measured evidence only, not resolvers.
Exact case IDs, bit counts, and rates must be re-read from current v2 metrics and fixture outputs before any public claim. This requirements page is not a metrics certificate.

9. Forbidden and allowed mechanisms

Forbidden as PGS inference (Must not): trial division; Miller-Rabin; ECPP; PARI primality; isprime; nextprime; sieve-backed prime generation; gcd; N % x as a factor selector; divisibility selectors; product closure checks; hidden factors; audit labels inside inference; factor APIs; random search; fallback search when unresolved.

Allowed transport facts (inference)

  • floor(N / anchor), floor(N / reset_endpoint), floor(N / reset_deadline_value)
  • previous public endpoint before a transported coordinate
  • differences between transported reset and deadline images
  • equality of public transported coordinates and reset signatures
  • GWR-selected carrier fields derived from chamber-reset state

Allowed classical roles

  • Downstream audit (factor confirmation after emit)
  • Benchmark comparison surfaces (clearly labeled)
  • Legacy prefilter paths elsewhere in the repo (not this resolver)

12. Acceptance criteria

A1 is accepted only when all Must criteria below pass. Measured rates are reported exactly; they do not become theorems.

Formal verification procedures, suite IDs, phase gates, and pass/fail rules: A1 formal test plan (document id A1-TP).

  • AC-01 Versioned algorithm document expresses every inference step in PGS objects; no classical selector in the rule text.
  • AC-02 GWR-carrier transport closure predicates are named, tested, and separate from audit.
  • AC-03 Structural certificate schema + standalone verifier exist; green tests on fixed fixtures.
  • AC-04 Known v2 resolved cases remain resolvable (or are reclassified with an explicit residual migration note).
  • AC-05 Known honest unresolved cases still emit unresolved (no silent “resolution” via classical gates).
  • AC-06 At least one corpus at 128-bit and one at 256-bit published with resolution rate, residual histogram, and full traces for every unresolved case.
  • AC-07 512-bit instrumentation path exists (even if resolution rate is low or zero); unresolved emissions remain well-formed.
  • AC-08 Inference vs audit separation verified by code review and automated import/guard tests where feasible.
  • AC-09 Continuity surfaces updated: track entry in status map or cryptology README; residual ledger path recorded.
  • AC-10 No claim language in docs upgrades measured endpoint classes to factorization theorems or RSA break claims.

14. Falsification plan (pre-register before claiming gains)

Every new carrier-closure predicate or scale claim must ship with a pre-registered adversarial probe. Attempted falsification is a first-class artifact (Track A4).
ProbeWhat would falsify the intended gain
Carrier-misalignment constructions Predicate “resolves” cases only by smuggling classical selection, or collapses known resolved cases to unresolved without residual progress.
False-positive endpoint classes Closure emits endpoint classes that fail independent certificate consistency (verifier red) or require audit factors to select.
Square-branch stress inside moduli Resolver path silently ignores high-utilization square branches and cannot export them.
Determinism replay Two runs of the same public input disagree on class or residual.
Import boundary test Inference graph reaches factor/MR/gcd helpers.

15. Metrics contract

Extend v2 summary/survivor fields. Each run must report:

  • case_id, bits, N, center=isqrt(N)
  • algorithm_version, git_commit
  • closure_status or residual code
  • certificate presence flags (lower, upper, corrected)
  • rule_id
  • step counts, active carrier stats (d4_count / carrier pairs as available)
  • resource notes: wall time, peak memory (measured)

Aggregate reports: resolution rate by bit length, residual histogram, certificate verify pass rate, audit match rate (audit sidecar only).

18. Definition of done (A1 program upgrade)

A1 is done as a program upgrade when:

  1. P0-P5 acceptance criteria AC-01 through AC-10 are satisfied.
  2. At least one 256-bit public instrumented corpus exists with certificates or honest residuals for every case.
  3. 512-bit path runs without classical fallback and emits well-formed outputs.
  4. Verifier is independently usable on published certificates.
  5. Cross-front export to square-branch or state-budget is documented with at least one measured handoff note.
  6. Public framing states clearly: structure reading and certification, not RSA break.
Recommended immediate next move (from counsel, preserved): Stand up or formally designate the endpoint-resolver-v3 track, produce the public walk-through of existing cases, then implement minimal GWR-carrier transport closure predicates against fixed resolved vs unresolved fixtures.
