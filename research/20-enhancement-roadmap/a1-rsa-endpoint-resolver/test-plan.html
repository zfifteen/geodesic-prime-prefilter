Enhancement A1 · Formal test plan

Test plan for the PGS-native RSA modulus endpoint resolver

This plan verifies that A1 implements the requirements in a1-rsa-endpoint-resolver/index.html: locked endpoint chains, floor transport, reciprocal closure, GWR-carrier transport closure, structural certificates, and honest unresolved residuals, without classical selection inside inference.

ID: A1-TP status: plan (not yet executed as a suite) covers: AC-01 to AC-10 phases: P0 to P6 does not prove factorization theorems
Success meaning. Tests pass when the resolver obeys the PGS contract and emits well-formed certificates or unresolved residuals. A high resolution rate is a measured statistic, not a pass condition for the program upgrade, and never upgrades to a factorization theorem.

1. Purpose and scope

1.1 Purpose

  • Prevent classical drift (gcd, MR, factor APIs, product closure) from entering inference.
  • Lock regression on known resolved and honest unresolved fixtures from RSA v2.
  • Verify GWR-carrier transport closure predicates as named, deterministic rules.
  • Verify structural certificate schema and standalone verifier behavior.
  • Exercise 128-bit, 256-bit, and 512-bit instrumentation paths with residual completeness.
  • Pre-register and run adversarial probes that would falsify claimed gains.

1.2 In scope

  • Public-input inference path for moduli (fixtures and generated corpora).
  • Certificate emit + verify path.
  • Residual taxonomy completeness and stability.
  • Audit sidecar separation (audit after inference only).
  • Documentation and continuity gates required by AC-01, AC-09, AC-10.

1.3 Out of scope (see also §16)

  • Proving new universal theorems in PROOF.md.
  • Claiming production RSA breaks or factoring results as test pass criteria.
  • Lean formalization of certificates (Track B; optional later mirror).
  • Replacing the production prime generator stream contract.

2. Test principles (PGS contract)

PrincipleTest implication
PGS-first inference Every inference test uses only public case fields and PGS objects. No private factors in inference inputs.
Unresolved is success of honesty Known unresolved fixtures must remain unresolved (or migrate with versioned residual notes). Silent classical resolution fails the suite.
Audit after, never chooses Audit tests live in a separate module/process graph. Inference packages must not import audit factor helpers.
Determinism Identical public inputs + algorithm version yield identical endpoint class or residual (bit-identical or documented exact-arithmetic equivalence).
Status separation Reports label measured rates separately from pass/fail contract checks. No “proved” language in test summaries.
Falsification first-class New carrier predicates require a pre-registered probe (suite ADV) before merge.

4. ID conventions

TP-<LEVEL>-<NNN>[-variant]

Examples:
  TP-RG-001     regression: known resolved fixture set
  TP-ADV-003    adversarial: false-positive class emission
  TP-SC-256-01  scale corpus: 256-bit well-formedness

Every automated test function name should include the TP id in its name or docstring. Every TP id maps to one or more requirement ids (FR / AC) in §8.

12. Pass / fail rules

12.1 Hard fail (suite red)

  • Forbidden classical mechanism observed in inference path.
  • Known unresolved fixture silently resolved without residual migration note.
  • Known resolved fixture fails without migration note.
  • Non-determinism on fixed public inputs.
  • Certificate claimed but verifier fails.
  • Unresolved emission missing residual code or required diagnostics.
  • Audit labels present in inference records.
  • Claim language fails TP-DOC-003 in release docs.

12.2 Soft fail (block release, allow research branch)

  • Scale corpus size below guidance but path works (must document deficit).
  • Optional grammar probe instability (must not affect resolver emit).
  • 1024-bit stretch not present.

12.3 Not a fail

  • Low or zero resolution rate on large bit lengths when residuals are honest and complete.
  • Audit mismatch on a class that is structurally consistent but not a factor (audit axis only).
  • Hypothesis probes that correctly falsify a candidate predicate (ADV success as science).

13. Reporting artifacts

Every formal run writes:

output/a1-test-runs/<date>_<git_commit>_<suite>/
  summary.json          # suite, pass/fail, counts, algorithm_version, git_commit
  cases.jsonl           # per-case emit (inference fields only)
  residuals.jsonl       # unresolved only, full diagnostics
  certificates/         # structural certificates when emitted
  verifier_report.json  # accept/reject counts
  audit_sidecar.jsonl   # optional; physically separate
  measured_metrics.json # rates, histograms, resources (measured only)
  attempt_log.md        # for ADV: pre-register link + outcome

CI or local gate should print a one-screen summary separating contract pass/fail from measured rates.

15. Execution checklist (operators)

  • Confirm public fixtures contain no private factors in inference inputs.
  • Run continuity baseline pytest; record pass count.
  • Run TP-RG-001/002/003 on frozen golden sets.
  • Run TP-BD-001 (and TP-BD-002 if enabled).
  • If new carrier predicate: ensure ADV pre-register exists; run TP-ADV-001/004/005.
  • If certificates changed: run TP-CT-001 to TP-CT-005.
  • Before claiming AC-06: run TP-SC-128-01 and TP-SC-256-01; publish measured metrics separately.
  • Before claiming AC-07: run TP-SC-512-01.
  • Before calling A1 done: complete DOC claim scan TP-DOC-003 and continuity TP-DOC-004.
  • Archive full output/a1-test-runs/... tree with git commit pin.

16. Out of scope and anti-patterns

Do not mark A1 tests green because audit found factors. Do not treat resolution rate thresholds as theorem evidence. Do not add Miller-Rabin “just to confirm” inside inference tests. Do not delete unresolved fixtures to improve pass rate. Do not edit PROOF.md theorem status from this plan.

Relationship to requirements

This test plan is the verification companion to A1 requirements. Implementation may refine TP procedures but must not drop Must coverage without an explicit residual migration note and human approval.
