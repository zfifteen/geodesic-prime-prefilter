Critical Issues

1. Derivation script uses non-existent API

The script contains:

anchor = pgs.previous_public_endpoint_before(target)

This function does not exist.

The actual surface (from pgs_inference_backend.py and run_experiment.py) is:

  • previous_endpoint(value, bound=...) in run_experiment.py (recommended entry point)
  • backend = get_backend_for_value(value); backend.previous_endpoint(value, bound)

The script will fail at import/execution time. A corrected minimal version would look like:

import sys from pathlib import Path import json import gmpy2 ROOT = Path('/Users/velocityworks/IdeaProjects/prime-gap-structure') sys.path.insert(0, str(ROOT / 'research/06-cryptology-rsa/experiments/live-solver/rsa-v2')) from run_experiment import previous_endpoint # ... load N and compute target as in the plan ... target = gmpy2.mpz(1) << int(ratio * N.bit_length()) anchor = previous_endpoint(target) # note: uses default RULE_X_CANDIDATE_BOUND internally print("Exact Deep Anchor:", anchor)

2. The ratio remains side-information

While the script correctly reads only the public 'n' field, the hardcoded ratio = 0.3994140625 was computed by analyzing the secret small-factor bit lengths of the challenge_like family. Selecting the target band using this specific number is still the injection of corpus-derived external knowledge.

This is acceptable only because the plan now consistently labels the activity as a family-specific characterization experiment. It would be unacceptable if the same technique were proposed for blind public N.

3. High-scale previous_endpoint at target depth is unproven

The target is ~2**102. HighScaleBackend.previous_endpoint performs a chunked backward search using chamber_reset_certificate (C first, then Python fallback) followed by divisor segment scans.

Backend comments explicitly note limitations and guards for anchors in the 90–128+ bit range. The derivation may return None, take a very long time, or exercise the documented "limitation" paths. This must be treated as part of the experimental data, not assumed to succeed.

4. "PGS Object" language vs. reality

The section title "Retrieve PGS Object (The Anchor)" is good in intent. However, because the starting location was chosen using external ratio knowledge, the resulting anchor is a PGS object located at a non-canonical, externally seeded position. This is fine for the stated experiment but should not be described as the solver "finding" the right place through structure alone.
