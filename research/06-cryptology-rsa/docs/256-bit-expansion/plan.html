PGS RSA v2: 256-Bit Scale Expansion

Goal-oriented implementation plan • research/06-cryptology-rsa • 2026-07-04

Primary target: Extend the live reciprocal PGSPG endpoint-chain certificate runner and its calibration ladder from the current 40/64-bit toy rungs to 128-bit and 256-bit scales while preserving the exact public-inference + separate-audit contract and PGS-native reasoning frame.

Goal

Make the deterministic public PGS endpoint-structure mechanism (locked endpoint chain → floor transport → reciprocal closure → structural certificate) produce auditable results on cryptographically relevant 128-bit and 256-bit moduli using the same live v2 runner used for the 40-bit and 64-bit successes. Deliver explicit status for each new rung: resolved (with closure reason) or unresolved (with precise PGS-native reason), supported by full diagnostic sidecars.

Strongest supported framing (per current contract): The mathematical objects are scale-invariant in definition. The practical limit is the cost and fidelity of PGSPG reset-certificate construction at the required anchors.

Current Baseline (Exact)

  • Live cases (post-expansion): 40-bit resolved deadline-sig true; 50-bit unresolved misalignment false; 64-bit mutual-closure true; 128-bit (127) unresolved_missing_lower false; 256-bit unresolved_missing_lower false. High-scale bridge relaxed and exercised.
  • Baseline before: rsa_v2_40bit_static_001 (resolved via deadline-signature correction, 0 steps, factor_found=true), rsa_v2_50bit (unresolved_by_reciprocal_carrier_misalignment), rsa_v2_64bit_static_001 (resolved via mutual_certificate_closure after 1162 steps, factor_found=true).
  • Runner: experiments/live-solver/rsa-v2/run_experiment.py + pgs_inference_backend.py + pgs_chamber_reset_state_certificate (Python) + partial HighScaleBackend (currently returns None for anchors > 2^60).
  • Fixtures: data-ladder/rsa-v2/ (ladder_spec.json public-only + audit_spec.json separate + build_ladder_fixtures.py + generate_ladder_rung.py).
  • Scale infrastructure already present: scaleup_corpus.json contains multiple 256-bit balanced/moderate/challenge_like cases with known p/q; geofac_scaleup probes; C high-scale-pgs (Apple Silicon GMP) with certificate structs and research probes; large_bit_fixtures.jsonl.
  • High-scale gap: ctypes bridge guards >60-bit and the extracted dicts currently lack full tail lists needed for deadline logic.

Required PGS Frame (Non-Negotiable)

locked PGS endpoint chain → floor transport through modulus → reciprocal endpoint closure → modulus-link residual → structural certificate or unresolved state

Public inference reads only N (plus deterministic previous_public_endpoint_before derived from PGS chamber mechanics). Audit (p, q) is strictly downstream. Classical methods (gcd, product, isprime inside inference, candidate search as chooser) are forbidden for endpoint-class emission.

Technical Considerations & Known Surfaces

  • Backend choice: get_backend_for_anchor already routes on size. SmallIntBackend (Python divisor segment + pgs_chamber) will be used for 128-bit if anchors < some practical Python limit; HighScale for 256-bit.
  • Certificate completeness: Deadline logic depends on tail_after_reset_offsets and lower_d_threat_offset. Current HighScale dict hard-codes empty lists, this must be fixed before any 256-bit deadline-signature result can be claimed.
  • Generation: generate_ladder_rung.py is the canonical deterministic method for "static" ladder rungs. scaleup_corpus is useful for challenge-like variety and blind-routing experiments.
  • Performance: With candidate_bound=128 the local segment is tiny; cost is dominated by number of chain steps × cost of one chamber certificate. Expect to measure and publish this.
  • Existing 256 work: Align (do not duplicate) with pgs_geofac_scaleup, 256 center priors, and competition probes. The certificate runner is a different (stricter, public-structure) lens.

Risks & Shape Guards

Shape feels wrong if:
• Any inference path inside run_experiment or pgs_inference_backend calls gcd, product, isprime as a chooser, or reads audit factors.
• A new rung is declared "solved" before audit_experiment reports factor_found=true.
• High-scale bridge is hacked with Python fallbacks that re-introduce slow full searches without using the C PGS chamber.
• We optimize only for the 256-bit cases we generated and lose regression on 40/64.
• Prose starts sounding like "we can now factor 256-bit RSA" instead of "this public modulus exposed the following endpoint-class structure under reciprocal transport; audit confirmed/denied."

Corrective: Stop, restate the locked-chain → transport → closure frame, return to explicit unresolved when the predicate does not fire, keep audit physically separate.

Invalidated or Out-of-Scope for This Campaign

  • Using the v2 certificate runner as a general-purpose factor finder with random seeds or ECM fallbacks.
  • Declaring scale success from geofac routing + prime-test counts alone (different mechanism).
  • Extending candidate_bound dramatically without cost accounting.
  • Any change that makes the 50-bit case "accidentally" resolve again without a new, stronger PGS predicate that also explains why 40/64 succeeded.
